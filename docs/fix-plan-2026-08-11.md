### W1 — 카드로 끝나는 턴의 종료 처리 (P0, 뿌리 하나·증상 둘)

어젯밤 P0 두 건은 같은 뿌리의 앞뒷면이다. 검증으로 코드 경로까지 확정됐다.

  "없는 것을 오류로 오판". `SessionOrchestrator.cs:1276`의 `_assistantTurns.ContainsKey`가 false →
  `:1277-1287`이 "could not recover an assistant response" system/error 기록 → **`:1289-1291`이 세션을
  Failed(패널 blocked)로 강등**. 카드 툴 3종이 모델에게 "End your turn now"로 최종 텍스트 없이 끝내라
  지시하므로(`DynamicToolDispatcher.cs:827/1256/1426`) 카드 턴은 결정론적으로 agentMessage 0건. 라이브 6/6 일치.
- **증상 B — ask 답변 시 working 세션 queued 영구 사망 (P0, 세션+대화 전손)**: `SubmitMessageAsync:147`이
  Running을 거부하지 않고 통과시켜 상태를 Waiting으로 덮고 백그라운드 턴 기동 → `_sessionGates`(세션당 1)를
  이전 턴이 쥔 채 `WaitForTurnOutcomeAsync`에 **전체 턴 타임아웃이 의도적으로 없어**(`:1090` 주석) 무한 폴링.
  resume은 halt만 풀고 게이트를 안 건드림, retract-last도 게이트를 해제하지 않아(`:213-222`) 회복 불가.
  MaxParallelTurns=4라 이런 세션 4개면 정상 세션까지 마비.

**수정 설계**
1. (W1-a, S) 카드 발행 시 `_cardIssuedTurns[turnId]=kind` 마크. `CompleteTurnAsync`의 판정을
   `completed && !hasAssistant && cardIssued`면 오류 미기록 + 상태를 Failed 대신 **신설 `awaiting-user`(또는 Idle)**로.
   부수효과: `:1294`의 post-turn auto-tidy 게이트도 같은 조건을 쓰므로 카드 턴이 tidy를 안 돌리는 현재 동작 유지 여부 결정.
2. (W1-b, M) 활성 턴마다 CancellationTokenSource를 `_activeTurns`에 보관. interrupt/stop-current/retract-last가
   codex interrupt와 함께 그 CTS를 Cancel → RunTurnAsync가 즉시 빠져나오며 `:455` finally에서 게이트 해제.
3. (W1-c, S) 카드 답변 특례: 답변 대상 카드를 발행한 턴이 아직 활성이면 큐에 넣지 말고 먼저 interrupt 후 배달
   (카드는 정의상 "사람 대기"라 그 턴을 살려둘 이유 없음).
4. (W1-d, S) 안전망: `WaitForTurnOutcomeAsync`에 **무진행 상한**(마지막 item/상태 변화 이후 N분) 도입 —
   전체 턴 타임아웃이 아니라 진행 정지 감지라 `:1090`의 설계 의도를 안 깬다. sessionGate 획득에도 타임아웃을 둬
   실패 시 "영구 침묵" 대신 "설명된 실패"로.

**테스트**: fake codex가 영원히 inProgress → (a) 두 번째 SubmitMessage가 유한 시간 내 결론,
(b) retract 후 새 메시지가 Running 진입, (c) 굳은 세션 4개 뒤 5번째 세션 정상 시작.
오케스트레이터 단위: 카드 마크+assistant 0건+completed → 오류 미기록·Idle / 마크 없음+0건 → 기존 Failed 유지(회귀).

## 핵심 판단

핵심 안전 구조(single-writer, CAS fingerprint, 명시적 문서 타깃, 승인 흐름)는 **잘 잡혀 있고 이번에 실제로
작동함이 확인됐다**. 남은 문제는 구조 결함이 아니라 **경계 처리** — 카드로 끝나는 턴의 종료(W1), 브로커 생성
컴포넌트의 solve 완결(W2), GH 예외 다이얼로그 방어(W3)다. 이 셋(전부 P0, 전부 어제 라이브에서 관측)이
"완벽하게 안정적으로 작동한다"를 막는 실제 벽이고, GPT가 나열한 P1/P2 23건은 대부분 그 뒤에 온다.
